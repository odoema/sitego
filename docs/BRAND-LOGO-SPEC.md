# SiteGo Brand and Logo Specification

## Single source of truth

Use the SiteGo brand mark from the repository's canonical favicon/logo asset rather than recreating it independently in each surface.

## Required surfaces

- Website favicon
- Website header/hero mark
- Plugin icon
- README/project avatar
- Release graphics
- Social preview image
- Future desktop application icon

## Harmonization rules

1. One primary mark and one compact icon.
2. Preserve the same proportions and clear space.
3. Do not stretch, skew or redraw the symbol per platform.
4. Keep light-background and dark-background variants visually identical in geometry.
5. Use the same wordmark typography across product surfaces.
6. Export platform-specific sizes from the master asset instead of resizing screenshots.
7. Keep the repository master asset under version control and document every derived asset.

## SiteGo visual principle

The visual identity should communicate trustworthy publishing: local control, a clear path to the web, and a successful deployment signal. Avoid generic cloud/rocket imagery.

## Next implementation step

When a local SiteGo project folder is supplied, run SiteGo inspection first, identify all changed logo/brand assets, select only the approved logo files, then publish and verify the affected website.
