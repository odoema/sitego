# SiteGo Distribution and Growth Plan

## Primary channel: ChatGPT/Codex plugin directory

Submit SiteGo to the universal plugin directory after the product passes packaging, security, and end-to-end review. Public plugins are discoverable across supported ChatGPT and Codex surfaces.

## Developer channels

1. GitHub repository — canonical source, issues, releases and examples.
2. GitHub Pages — product website, documentation, demos and changelog.
3. VS Code Marketplace — future companion extension for developers who want publishing status inside the editor.
4. npm — future CLI distribution if a stable command-line package is introduced.
5. MCP/plugin communities — publish technical integration examples and reusable workflows.

## Launch channels

1. Product Hunt — launch the first stable public release with a short demo and a clear problem statement.
2. Hacker News — use a genuine Show HN post focused on the engineering problem and what is different about SiteGo.
3. Reddit developer communities — share tutorials and lessons learned, not repeated advertisements.
4. LinkedIn — founder build story, short deployment demos, case studies and release notes.
5. X — short technical clips, release threads and GitHub links.
6. YouTube — 60-second demo, full setup tutorial and failure-recovery walkthroughs.
7. Developer newsletters and podcasts — pitch the local-first deployment/security angle.

## Growth strategy

### Phase A: 25 design partners
Recruit developers, students, agencies and small teams who deploy static sites or web apps. Measure successful first publish, verified-live rate, and time-to-first-deployment.

### Phase B: public launch
Publish the plugin, website, GitHub release, demo video and Product Hunt page in the same week. Make the demo prove the complete path rather than showing slides.

### Phase C: proof
Turn successful deployments into short case studies. Publish benchmarks, failure stories and fixes. Build trust through transparent changelogs and public issue tracking.

### Phase D: ecosystem
Add VS Code support, hosting adapters, templates and integrations only when repeated user demand justifies them.

## Messaging

Core promise: **From local folder to verified live website — safely.**

Supporting message: **SiteGo does not confuse “pushed” with “deployed.”**

## Metrics

Track:

- Plugin installs
- First successful inspection
- First publish attempt
- Verified-live deployments
- Publish failure rate
- Secret-scan blocks
- Weekly active users
- Repeat publishing users
- GitHub stars/forks
- Issue-to-release cycle time
